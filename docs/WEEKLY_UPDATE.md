# 每周更新手册

## 开始前

1. 从 GitHub 拉取最新 `main`。
2. 阅读 `AGENTS.md` 和 `docs/PRD.md`。
3. 新建本周分支，不直接在旧副本上改。
4. 先运行一次 `npm test`，确认起点可构建且模板未变。

## 更新顺序

1. 冻结本周报告日和各栏目时间窗口。
   企业动态查询中，`importance` 是财汇新闻舆情的“重要/一般”标签；查询优先使用证券代码。一般兜底先按 `importance="一般"` 查询，不预设一级资讯分类，返回后再本地筛选“公司经营/资本运作”并执行子分类排除。
2. 企业动态：使用 `gsdt`，仅限 `data/customer-universe.json` 客户池；先逐家查询并优先保留滚动近一周（含报告日在内连续7个自然日）的“重要”记录。若全量客户池的重要记录不足 8 条，再随机抽取客户补查“一般”记录；一般记录仅限“公司经营/资本运作”，并排除 A级纳税人、工商变更、授信情况、关联交易、投资理财、利润分配、知识产权、政府补贴、应收账款大幅增加、公司授信额度变化、担保、股权质押、解除质押。最终不超过 10 条、企业不超过 8 家；缺口如实保留，不得回补历史记录。
3. 行业热点：使用 `hyrd`，六个行业按 PRD 取数；研报只用于发现与理解事件，最终保留可核验公开原文。
4. 微信公众号：先用 `rn-wechat-extract` 读取正文，再按栏目标准整理。
5. 价格指数：按 PRD 指标原名和窗口更新 `data/prices.json`。
6. 财务数据：仅用 `a-stock-data` 更新 `data/financials.json`；不调用 PRD 禁止的四个通联财务接口。
7. 长三角项目审批动态：通过财汇 MCP 查询滚动近两周内江浙沪皖审批类、备案类和核准类项目，不限制最新项目阶段；保留总投资严格大于 5000 万元的项目，与现有记录去重并移除窗口外数据后更新 `data/reference.json`。
8. 半年度披露和土地交易：土地按报告日滚动近 1 个月从官网更新，与现有记录去重并移除窗口外数据；其余按 PRD 的附件/官网口径更新 `data/reference.json`。
9. 政策：政府网站优先；只在现有政策基础上新增并去重，不删除历史政策；只有找到真实权威解读时才提供解读入口，不自行添加套话式“解读”。
10. 直播中心：先运行 `npm run live-center:check` 审查 `docs/视频地址.xlsx` 是否与 `data/content.json` 一致；检测到变化后核对标题、六个行业分类和 HTTPS MP4 地址，再运行 `npm run live-center:sync -- --date YYYY.MM.DD` 同步。工作簿不可用、分类不完整或地址校验失败时保留现有数据并报告问题。
11. 尽调百宝箱：运行 `npm run due-diligence:check` 遍历项目根目录 `pdf/` 并核对 PDF 清单、文件哈希和数量；发现新增、删除或内容变更时，先核对文件类型后运行 `npm run due-diligence:sync -- --date YYYY.MM.DD` 更新清单。仅收录 PDF，不将其他格式混入下载或 ZIP。

## 完成后

1. 运行 `npm test`，生成 `dist/index.html`。
2. 打开 `dist/index.html`，核对桌面端和手机端、导航、雷达、图表悬停、筛选、表格悬停全名和原文链接。
3. 用 `git diff` 确认普通周更只修改 `data/` 和必要的报告期文档，不含 `template/`。
4. 提交并推送本周分支，在 GitHub 创建 Pull Request（合并请求）。
5. 另一人检查来源、日期、客户池、六行业覆盖和自动验收结果后再合并到 `main`。

## Codex 周更提示词

> 这是固定模板周更。先读取 AGENTS.md、docs/PRD.md 和 docs/WEEKLY_UPDATE.md，使用仓库 skills 中的对应技能，严格按 PRD 取数。保持 template 和所有页面样式、布局、响应式、交互完全不变，只更新 data。完成后运行 npm test，检查 dist/index.html，并提交到新的 weekly 分支，不要直接合并 main。

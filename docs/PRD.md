# 长三角金融总部行业研究综合门户

> **版本冻结规则（最高优先级）**：以 2026 年 8 月 19 日下午确认并部署的周报版本为当前基准版本。后续每周更新仅修改数据和内容，不得主动修改页面样式、布局、字体、颜色、间距、交互和视觉结构。只有在用户明确提出“修改样式”或等价要求时，才允许调整视觉或交互表现；任何周报数据更新都不得借机改动页面模板。

> **默认周更含义**：用户提出“更新周报”“更新本周网站”“生成本周版本”或等价要求时，默认只授权更新各板块的时效性内容、数据、日期、来源和原文链接，不构成修改模板或样式的授权。所有取数继续执行本 PRD 各栏目最初确定的来源、接口、时间窗口、筛选标准和展示口径。

## 0. 每周更新操作指导（强制执行）

### 0.0 团队协作与项目技能

- GitHub 仓库是两位维护者共同使用的唯一现行版本；不得长期以各自 ZIP 副本并行修改。
- 仓库必须附带 `skills/` 中的项目相关 Skills，确保新电脑可按相同取数和写作规则工作。
- 每次周更先使用 `portal-weekly-maintainer` 读取本 PRD，再按栏目调用 `gsdt`、`hyrd`、`a-stock-data`、`rn-wechat-extract`、`agent-reach`、`datayes-macro` 和 `spreadsheets`。
- Skills 只提供工作规则和脚本，不得包含 Token、Cookie、账号密码或个人本机绝对路径。
- 普通周更应通过分支和 Pull Request 协作；自动检查通过并经另一人复核后，再合并到 `main`。

### 0.1 唯一页面模板

- 每周更新必须以 **2026 年 8 月 19 日下午确认并部署的最终版本**为唯一页面模板。
- GitHub 仓库中的固定模板由 `template/index.template.html` 与 `template/radar-scan.html` 共同组成。
- 每周构建后的单文件成品为 `dist/index.html`；历史认可成品对照为 `baseline/2026-08-19-final.html`。
- 模板 SHA-256 校验值统一记录在 `template-lock.json`，由 `npm test` 自动核对。
- 未经用户明确提出样式修改，不得替换模板、重新生成视觉方案或引用其他历史 HTML 版本。

### 0.2 每周允许更新的内容

每周仅更新各板块具有时效性的业务内容和对应数据，包括但不限于：

- 企业动态；
- 行业热点；
- 价格指数及其日期、数值和变化；
- 财报速递及披露时间表；
- 行业横向财务指标；
- 政策解读；
- 上海土地招拍挂信息；
- 页面中的报告期、更新日期、来源和原文链接。

更新入口仅限 `data/content.json`、`data/financials.json`、`data/reference.json`、`data/prices.json` 及经用户明确授权更新的 `data/customer-universe.json`。不得把每周数据更新扩展为模板改版。

### 0.3 每周禁止改动的内容

除非用户明确提出修改样式，否则以下内容必须与模板完全一致、原封不动：

- 页面结构、栏目顺序和导航关系；
- 配色、字体、字号、字重、行高和间距；
- 卡片、表格、图表、雷达、按钮和标签的视觉样式；
- 桌面端和手机端响应式规则；
- 动画、悬停提示、筛选和其他交互行为；
- 页头、Logo、主标题、页尾署名及整体视觉语言。

不得因内容长度变化、数据缺失或实现便利而擅自调整模板。内容过长时，应按既有组件规则做摘要、截断或悬停展示；确需改变模板时，必须先获得用户明确确认。

### 0.4 取数与内容规则

- 每周更新继续严格执行本 PRD 各板块最初确定的取数范围、数据源、接口、筛选标准、时间窗口、可比公司分组和展示口径。
- 不得自行新增指标、推导指标、装饰性数字或用户未指定的栏目。
- 企业动态继续走 `/gsdt`，行业热点继续走 `/hyrd`。
- 财务报表与财务指标继续通过 `a-stock-data` 获取，并遵守本 PRD 中禁止调用的通联数据接口清单。
- 微信公众号文章使用 `rn-wechat-extract` 读取正文后再整理，不得以“无法打开”为由添加模糊占位说明。
- 所有外部内容继续保留来源、日期和原文链接；政策、土地等栏目继续执行本 PRD 已规定的官方来源优先规则。

### 0.5 每周更新流程

1. 以本 PRD 为最高优先级，读取本周报告日和各板块更新时间窗口。
2. 按各板块既定规则抓取、筛选和核验数据与内容。
3. 只更新 `data/` 中的数据和时效性文案，不修改 `template/` 的结构与样式。
4. 生成预览并核对桌面端、手机端、图表悬停、筛选、原文链接和表格完整显示。
5. 对比更新前后的模板结构和样式；若存在非用户授权的视觉差异，必须撤回该差异。
6. 提交 GitHub 时，提交说明应列明本周更新的数据日期、板块和来源，不得混入样式调整。

### 0.6 周更验收标准

- 页面视觉与固定模板一致；
- 仅时效性内容、数据、日期、来源及链接发生变化；
- 各板块取数符合本 PRD 原始规则；
- 无新增的未授权指标、栏目或解释性占位文字；
- 桌面端和手机端均可正常使用；
- 原文链接、图表提示、筛选和表格展示正常；
- GitHub 中的 PRD、数据文件和最新周报版本保持同步。

## 1. 项目定位

### 1.1 门户名称
**长三角金融总部行业研究综合门户**

### 1.2 核心目标
打造一个面向长三角金融总部行业研究与业务支持场景的综合门户，将产业链资讯、上市公司财报、行业横向对比、政策与重大产业投资信息集中到统一入口中。

门户应重点满足以下目标：

- 信息集中：将产业研究相关内容统一沉淀在一个门户中。
- 更新高效：支持周度、季度及事件驱动式更新。
- 数据可视化：重要价格、指数和横向对比指标以图表形式呈现。
- 信息可溯源：凡引用外部资讯、政策、公告或政府公开信息，必须标注来源并可点击跳转至原文。
- 中文优先：核心业务信息、公司名称、栏目名称、标签等均优先使用中文。
- 长期扩展：页面结构应支持后续增加行业、企业、指标和新栏目，而无需大幅重构。

---

## 2. 总体信息架构

门户设置三个一级业务模块：

1. **产业链周报**
2. **财报速递**
3. **营销提示**

建议采用适合高信息密度研究场景的 Dashboard / 研究驾驶舱式布局，而非传统资讯门户的长页面堆叠方式。

# 3. 一级模块一：产业链周报

## 3.1 企业动态

### 功能定位
集中展示重点企业近期重要动态。

财汇新闻舆情中的“重要/一般”以返回的 `importance` 标签为准，不与资讯分类混同；逐家查询优先使用客户池证券代码。一般兜底查询不预设一级资讯分类，而是在返回的关联企业标签中筛选一级分类“公司经营”或“资本运作”，再执行子分类排除。

### 实现要求
- 企业动态数据统一调用 **`/gsdt` Skill** 获取。
- 每条动态建议至少包含：
  - 公司名称
  - 标题
  - 摘要
  - 事件日期 / 发布时间
  - 信息来源
  - 原文链接
- 公司名称必须使用**官方中文名称或通行中文简称**。
- 禁止为了所谓“科技感”将中文公司名转换为小写拼音、无意义英文简称或难以识别的字母组合。
- 点击来源或“查看原文”后，应直接跳转至原始信息页面。
- 企业动态严格限定为本地客户池内滚动近一周（含报告日在内连续7个自然日）的最新动态。先逐家查询并优先保留“重要”记录；若全量客户池查询后的重要记录不足 8 条，才从 69 家客户中随机抽取公司补查“一般”记录。一般兜底仅允许一级分类“公司经营”或“资本运作”，并排除 A级纳税人、工商变更、授信情况、关联交易、投资理财、利润分配、知识产权、政府补贴、应收账款大幅增加、公司授信额度变化、担保、股权质押、解除质押等子分类。最终总动态不超过 10 条、企业不超过 8 家；缺少合规记录时如实保留缺口，不得回补历史新闻、使用非名单企业、无来源内容或占位数据。

## 3.2 行业动态

### 功能定位
展示与重点产业链相关的重要行业新闻、供需变化、重大项目、技术进展及市场变化。

### 实现要求
- 行业动态数据统一调用 **`/hyrd` Skill** 获取。
- 每条内容至少包含：
  - 所属行业
  - 标题
  - 摘要
  - 发布时间
  - 信息来源
  - 原文链接
- 外部引用必须能够直接跳转原文。
- 内容应优先呈现对行业研究、企业经营和金融业务判断有价值的事实信息。

## 3.3 直播中心

直播中心为与“产业链周报”“财报速递”“营销提示”并列的一级门户模块，并在总览研究工作台提供独立入口。模块展示人工智能、高端制造、集成电路、生物医药、新能源和化工新材料六类直播回放。视频标题和 HTTPS MP4 地址以项目内 `docs/视频地址.xlsx` 为唯一来源；页面按行业筛选并直接播放。每周更新先审查工作簿与数据是否一致，只有通过分类与地址校验后才同步数据。

## 3.4 价格指数观察

### 3.3.1 数据来源
后续接入用户提供的**通联数据 Token / API 接口**，用于调用所需价格与指数数据。

### 3.3.2 数据频率
系统仅需考虑以下两种更新频率：

- 日频
- 周频

通常以周频数据为主。

**暂不考虑月频数据。**

### 3.3.3 图表展示
每个价格 / 指数以可交互折线图展示。

必须满足：

- 默认展示**最近三个月**的数据。
- 不默认展示三年长周期，避免近期波动被过度压缩。
- 横轴：日期 / 周期。
- 纵轴：价格或指数值。
- 鼠标悬停时显示：
  - 日期
  - 当前数值
  - 单位
  - 对比变化
- 图表应适应不同单位和量级。
- 页面重点为**纯数据展示**，不在图表上增加新闻事件、政策事件或原文跳转标记。

### 3.3.4 变化对比规则
> 这里按照业务定义进行“同期变化”展示，不采用传统财务报表中的严格同比口径。

- **日频数据**：当前值与 **7 天前**数据进行对比。
- **周频数据**：当前值与 **约 1 个月前（建议按 4 周前）**数据进行对比。

建议同时显示：

- 当前值
- 对比期值
- 绝对变化
- 百分比变化
- 上升 / 下降方向

### 3.3.5 固定指标清单

以下指标均通过**通联数据接口**取数。

#### 取数与标题规则
- API 查询时优先使用下列**指标原名**进行匹配和取数。
- 网站图表标题必须显示对应的**指标原名**，不得擅自改成简称、英文别名、拼音或其他自定义名称。
- 用户已明确给出单位的，标题 / 数值展示中保留该单位。
- 未明确给出单位的指数类指标，优先按照通联接口返回的单位展示；如接口本身无单位，则按指数点值展示。
- 如通联接口中的实际字段名与下列名称存在细微格式差异，应以“语义一致且唯一匹配”为原则进行字段映射，但前台标题仍按本文档规定的原名展示。

#### 一、有色指数
1. **镍铁:价格**（元/镍点）
2. **钢材价格指数:钢材**（元/吨）
3. **电解铜:价格**（元/吨）

#### 二、电池材料指数
1. **碳酸锂:价格**（元/吨）
2. **硫酸钴:价格**（万元/吨）
3. **电解液:价格**（元/吨）

#### 三、能化指数
1. **现货价:OPEC:一揽子原油**（美元/桶）
2. **成品油指数**
3. **期货收盘价:精对苯二甲酸(PTA):连二**（元/吨）
4. **涤纶POY:指数**

#### 四、集成电路
1. **价格指数:DRAM**

#### 五、船舶物流
1. **波罗的海运价指数:干散货(BDI)**
2. **中国新造船价格指数:CNTPI**

### 3.3.6 图表与对比规则适用于全部上述指标
- 默认展示最近 **3 个月**。
- 日频指标：与 **7 天前**数值对比。
- 周频指标：与 **4 周前**数值对比。
- 鼠标悬停显示日期、当前值、单位及对比变化。
- 该模块只做数据展示，不叠加新闻、政策或原文跳转标记。

# 4. 一级模块二：财报速递

## 4.1 行业横向对比

### 功能定位
按已确定的可比公司分组，对同一细分行业内上市公司的核心财务指标进行横向比较。

**可比公司分组以用户提供的《上市公司行业分类_相似类型汇总》附件为准，不由系统自动扩充或调整。**

### 4.1.1 可比公司分组

#### CMOS 图像传感器
- 思特威
- 豪威集团
- 格科微

#### 半导体硅片
- 沪硅产业
- 中欣晶圆
- 有研硅
- 立昂微
- TCL中环
- 西安奕材

#### 锂电池
- 国轩高科
- 欣旺达
- 亿纬锂能
- 宁德时代

#### 光伏
- 晶澳科技
- 天合光能
- 晶科能源
- 隆基绿能
- 阿特斯

#### 大炼化
- 东方盛虹
- 恒力石化
- 荣盛石化
- 新凤鸣
- 恒逸石化
- 桐昆股份

### 4.1.2 固定对比指标

行业横向对比统一展示以下 8 项指标：

1. **资产负债率**
2. **销售毛利率**
3. **销售净利率**
4. **应收账款周转天数**
5. **存货周转天数**
6. **营业收入同比**
7. **净利润同比**
8. **扣非后归属母公司股东的净利润（同比）**

指标名称在前台应优先使用上述中文名称，不得改写成无意义英文缩写或拼音。

### 4.1.3 财务数据来源

- 上述财务报表及财务指标数据统一调用 **`A Stock Data` Skill** 获取。
- **禁止通过通联数据获取任何财务报表或财务指标数据。切记不得调用以下通联数据 API：`fdmt_indi_rtn`、`dmt_indi_lqd`、`fdmt_bs_new_lt`、`fdmt_is_new_lt`。**
- 即使上述接口可用、已有 Token 或存在历史调用记录，也不得进行接口测试、试取数、兜底取数或批量调用。
- Codex / 后端应通过 `A Stock Data` Skill 查询各上市公司对应报告期的标准财务数据。
- 公司匹配应优先使用证券代码作为唯一标识；前台显示公司官方中文简称。
- 如 Skill 返回字段名称与本文档指标名称不完全一致，应在后端建立字段映射，前台仍使用本文档规定的中文指标名称。
- 不得在前端展示 Skill 调用过程、字段映射规则、接口参数或开发说明。

### 4.1.4 报告期与数据口径

- 支持按报告期切换，包括：
  - 一季报
  - 半年报
  - 三季报
  - 年报
- 默认展示最近一个已披露且同组公司具有可比性的报告期。
- 横向比较时应尽量保证同一张图中的公司使用**相同报告期、相同指标口径**。
- 若个别公司对应报告期尚未披露，应明确显示“未披露”或“暂无数据”，不得以其他期间数据混入同一横截面比较。
- 百分比类指标统一按百分比展示。
- 周转天数类指标统一按“天”展示。
- 数值精度应保持统一，避免同一图表中出现不一致的小数位。

### 4.1.5 交互图表

行业横向对比必须采用**可交互图表**，而不是仅提供静态表格。

#### 默认横向比较视图
建议使用横向或纵向柱状图：

- 横轴 / 分类轴：公司名称
- 数值轴：当前选择的财务指标
- 每次重点展示 1 个指标，避免 8 个不同量纲指标挤在同一坐标轴。
- 鼠标悬停时显示：
  - 公司名称
  - 报告期
  - 指标名称
  - 指标数值
  - 单位
- 支持点击图例、公司名称或筛选器控制显示范围。

#### 页面筛选器
至少提供：

- **行业分组切换**
- **报告期切换**
- **指标切换**
- **公司多选 / 单选高亮**

#### 排序
支持：

- 按指标值从高到低
- 按指标值从低到高
- 恢复附件中的默认公司顺序

#### 趋势查看
在用户选中单家公司或少量公司后，可切换到历史趋势视图：

- 横轴：报告期
- 纵轴：当前指标
- 多家公司以多条折线进行对比
- 鼠标悬停显示各公司对应报告期数值

趋势视图属于辅助交互；页面默认仍以**同一报告期、同组公司的横向比较**为核心。

## 5.1 尽调百宝箱

## 5.2 政策解读

### 六大行业

2. **生物医药**
3. **高端制造**
4. **人工智能**
5. **新能源**
6. **化工新材料**

### 更新逻辑
- 不要求每周强制更新。
- 重要政策一旦收录，可以长期保留。
- 新政策发布后按重要程度新增。
- 周报更新必须在既有政策清单基础上追加并去重，不得因进入新一期周报而删除历史政策。
- 政策卡片每页展示 6 条，筛选行业后从第 1 页重新分页。
- 支持按行业分类检索。
- 首次取数以报告日前最近一个自然月内、政府网站挂网的新出台政策为范围；后续新增政策保留历史记录。
- 每条政策优先收录政府网站原文；在互联网检索到可核验的权威解读时，同时提供解读入口。

- 发布时间
- 政策摘要
- 核心解读
- 可能影响的产业环节
- 信息来源
- 原文链接

### 解读原则

- 不做与门户业务目标无关的政治评论。

## 5.4 长三角项目审批动态

### 功能定位
在“营销提示”中展示长三角区域最近一周公开审批动态、且项目总投资金额超过人民币 5000 万元的建设项目，供业务人员识别新增产能、建设投资和潜在融资需求。

### 固定查询口径
- 地域范围：上海市、江苏省、浙江省、安徽省。
- 时间范围：滚动近两周，按财汇 MCP 对“近两周”的标准化日期区间执行。
- 立项类型：同时覆盖“审批类”“备案类”“核准类”。
- 项目阶段：不作限制，保留项目建议书、可研、初步设计、核准、备案、节能、用地、环评、规划许可等财汇返回的最新项目阶段。
- 金额门槛：项目总投资必须严格大于人民币 5000 万元；恰好 5000 万元不纳入。
- 数据来源：统一通过财汇 MCP 的“企业经营—投资建设项目—投资建设项目检索”获取，底层为各省市发改及政务平台公开档案。

### 数据处理与展示
- 财汇 MCP 查询参数应同时包含日期、江浙沪皖地区、项目投资金额，以及审批类、备案类和核准类三种立项类型；不设置项目阶段过滤条件。
- 接口返回后再次校验日期、地区、立项类型和金额边界，防止金额等于 5000 万元的项目混入。
- 表格固定且仅展示：备案日期、地区、项目名称、总投资（万元）、项目主体、国标行业一级、最新项目阶段。项目代码、项目类型、来源等其他字段不得加入该表格。
- 支持按省份、立项类型、投资金额区间、国标行业一级和最新项目阶段筛选；投资金额固定分为“5000万元—1亿元”“1亿元—5亿元”“5亿元以上”，区间依次按 `>5000且<10000万元`、`≥10000且<50000万元`、`≥50000万元`执行，避免边界重复。默认按备案日期从新到旧展示，同日项目按总投资从高到低排列。
- 表格使用宽表和横向滚动，不得为塞进单屏而压缩项目名称、项目主体和行业字段。
- 项目表格每页展示 30 条；任一筛选条件变化后回到第 1 页。
- “备案日期”按财汇 MCP 返回的“最新公告日期”展示；如该字段缺失，使用最新审批日期兜底。
- 财汇 MCP 未返回“国标行业一级”时，该表格单元格保持空白，行业筛选项中不生成“未返回”选项。
- 若某省或本周全部地区无符合条件的项目，应如实显示无记录，不得以金额未达门槛的项目补数。

### 周更规则
- 每期周报自动查询滚动近两周的完整项目结果，与现有记录去重合并，并删除滚动窗口以外的旧记录。

# 6. 全站信息源与引用规范

## 6.1 强制溯源
除“价格指数观察”等纯 API 数据展示模块外，凡引用外部信息，原则上必须：

1. 标注信息来源。
2. 标注发布时间 / 公告时间（如适用）。
3. 提供可点击的原文入口。
4. 点击后跳转至原始信息页面。
5. AI / 系统生成摘要不得伪装成原文。

## 6.2 信息源优先级
优先使用：

- 中国政府及地方政府官方网站
- 监管机构官方网站
- 交易所及上市公司公告
- 上市公司官方网站
- 行业协会
- 权威专业数据库
- 具有较高公信力的主流财经、产业和综合媒体
- 其他可以核验且具有明确原始出处的专业来源

## 6.3 政治敏感性与内容过滤
门户定位是**行业研究与金融业务支持**，因此信息选择应坚持：

- 以事实性、产业性、经营性信息为主。
- 对来源本身与具体文章内容分别评估。
- 即使来自国际主流媒体，也只提取与行业、企业、产业链、经营、市场相关的事实信息。
- 剔除与研究主题无直接关系的政治立场性、意识形态性、煽动性或攻击性表述。
- 不引用政治敏感、明显带有强烈政治对抗立场或可信度不足的来源作为核心依据。
- 摘要不得主动放大与产业研究无关的政治评价。
- 对可能存在争议的信息，优先回到政府、监管机构、公司公告等第一手来源交叉核验。

# 8. UI / UX 与视觉设计规范

## 8.1 设计风格
整体风格定位为：

**科幻感 + 未来复古（Future Retro）+ 专业金融研究驾驶舱**

视觉气质：

- 深色界面为主。
- 深蓝黑 / 深灰黑作为主要背景。

- 具有科技感，但不得以牺牲可读性为代价。
- 动效克制，避免娱乐化、游戏化和过度炫技。

## 8.2 Frontend Design Skill
在 Codex / 开发环境支持的情况下：

- **优先使用用户已安装的 Frontend Design Skill。**

- “本栏目用于……”

- 行业名称使用中文。
- 导航、按钮、指标、筛选器等优先使用中文。
- 可以保留行业内必要且通行的英文技术名词，例如：
  - CMOS
  - API
  - AI
  - 其他确有必要且用户容易理解的专业缩写

### 禁止
- 将中文公司名机械转成拼音。
- 使用小写拼音作为公司主名称。
- 为了“未来感”堆砌无意义英文短语。
- 使用用户无法快速识别的英文缩写代替清晰中文。
- 使用没有业务含义的英文标签作为页面主要视觉元素。

**科技感应来自视觉系统、数据呈现和交互设计，而不是来自英文堆砌。**

# 9. 页面与组件建议

## 9.1 首页
首页建议使用研究驾驶舱式布局，提供三个一级模块入口，并展示各模块最值得关注的最新内容。

### 首页品牌与主视觉
- 顶部品牌标识必须醒目展示：**长三角金融总部｜行业研究门户**。
- 品牌标识的字号、字重和视觉层级应明显高于普通导航文字。
- 首页主口号暂定为：**洞察产业脉动，链接金融未来。**
- 主口号下可使用简短业务文案，但不得出现开发说明、数据接入说明或 PRD 规则解释。

### 三大模块入口
- 首页只保留一组三大模块入口，避免在首屏按钮与下方卡片中重复出现相同入口。
- 三个入口分别为：
  - 产业链周报
  - 财报速递
  - 营销提示
- 三个入口采用整卡可点击方式，栏目名称、进入按钮和方向提示必须足够醒目。
- “产业链周报”“财报速递”“营销提示”等入口标签不得使用过小字号。
- 财报速递入口文案使用中性、专业的研究表达，例如：**洞察同业表现与经营趋势**。
- 禁止使用可能带有评价、贬低或优劣暗示的措辞，例如“看见同业之间的差异”。

首页可包含：

- 顶部全局导航
- 醒目的门户品牌标识
- 当前更新日期
- 一组三个一级模块入口
- 本周重点企业动态
- 本周重点行业动态
- 价格指数摘要卡片
- 最新政策
- 最新重大投资项目

首页内容不宜无限堆叠，应强调“最新、重要、可行动”。

## 9.2 通用组件
建议建立统一组件库：

- 信息卡片
- 来源标签
- 原文跳转按钮
- 数据表格
- 筛选器
- 日期筛选
- 行业标签
- 公司标签
- 交互折线图
- 横向对比图
- 指标卡片
- 空状态
- 加载状态
- 数据更新时间

# 10. 数据与技术设计原则

## 10.1 数据层与展示层分离
前端页面不得直接绑定某一个固定数据文件。

建议统一数据模型，由：

- API
- 数据库
- 抓取程序
- 手工维护数据
- 第三方数据接口

向前端提供标准化数据。

## 10.2 数据更新时间
每个模块应明确显示：

- 最近更新时间
- 数据所属日期 / 报告期
- 必要时显示数据频率

## 10.3 可扩展性
系统应能够在不重构核心页面的情况下：

- 新增行业
- 新增企业
- 新增价格 / 指数
- 新增财务指标
- 新增政策
- 新增重大投资项目
- 新增其他一级 / 二级业务模块

# 12. Codex 开发约束摘要

Codex 开始生成网站前，必须优先遵守以下规则：

1. 以本 PRD 为产品需求基线。
2. 优先调用已安装的 Frontend Design Skill。
3. UI 风格为科幻、未来复古、专业金融研究驾驶舱。
4. 全站中文优先。
5. 不得将中文公司名称改为拼音或无意义英文。
6. 不得通过堆砌英文缩写制造科技感。
7. 外部资讯、政策、公告、政府公开信息必须标明来源并提供原文跳转。
8. “价格指数观察”为纯数据可视化，不叠加资讯事件。
9. 价格 / 指数默认仅展示最近三个月。
10. 日频数据比较 7 天前；周频数据比较约 4 周前。
11. 财报速递当前仅建设行业横向对比，不展示财报披露时间表。
12. 首批横向对比行业为：大炼化、锂电池、光伏、CMOS 图像传感器、半导体硅片。
13. 政策解读覆盖：集成电路、生物医药、高端制造、人工智能、新能源、化工新材料。
14. 土地招拍挂首期仅覆盖上海市已成交土地。
15. 重大产业投资项目首期仅覆盖上海市，且总投资金额必须达到人民币 1 亿元及以上。
16. 不设置“是否为我行客户”等无法可靠判断的字段。
17. 所有外部内容应优先采用权威、可核验、与行业研究直接相关的事实性来源。
18. 页面设计必须组件化、响应式，并为后续新增行业、企业和模块预留扩展能力。
19. PRD / Markdown 中的功能定位、实现要求、设计意图、抓取规则、更新逻辑、字段解释等开发说明性内容不得直接显示在网站前台。
20. 网站前台不得出现“本栏目用于……”“建议展示……”“开发阶段应……”等自我解释式文案；最终 UI 只呈现业务内容、数据、必要标签、来源与交互。
21. 行业动态统一调用 `/hyrd` Skill 获取数据。
22. 企业动态统一调用 `/gsdt` Skill 获取数据。
23. “价格指数观察”固定使用本文档列出的 5 类 13 个指标，并通过通联数据接口取数。
24. 价格指数图表标题必须显示本文档指定的指标原名，不得擅自改名、缩写、翻译或改成拼音。
25. 有明确单位的指标必须保留单位；无明确单位的指数按通联接口返回单位或指数点展示。
26. 行业横向对比的公司分组必须以用户上传的可比组附件为准，不得自动增删公司。
27. 行业横向对比固定展示 8 项指标：资产负债率、销售毛利率、销售净利率、应收账款周转天数、存货周转天数、营业收入同比、净利润同比、扣非后归属母公司股东的净利润（同比）。
28. 上述财务数据统一通过 `A Stock Data` Skill 获取；优先使用证券代码查询，并在后端完成字段映射。
29. 横向对比图表默认使用同一报告期的同组公司进行比较，支持行业、报告期、指标和公司筛选，并提供交互式 Tooltip、排序及辅助趋势视图。
30. 首页顶部必须醒目展示“长三角金融总部｜行业研究门户”品牌标识。
31. 首页主口号暂定为“洞察产业脉动，链接金融未来。”
32. 首页不得重复设置相同的模块入口；三大模块入口采用整卡可点击方式并突出栏目名称与进入动作。
33. 三大入口标签字号不得过小；“财报速递”入口使用“洞察同业表现与经营趋势”等中性专业措辞。
34. “地域范围”“项目门槛”“固定可比公司分组”“同一报告期、同一指标口径”等开发或数据筛选规则不得直接展示在网站前台。
35. 禁止展示“产业链温度”“行业热度”“信号强度”等未在本 PRD 中定义且无真实来源的自创指标或示意数值。
36. “营销提示”展示长三角项目审批动态，固定覆盖上海、江苏、浙江、安徽，时间窗口为滚动近两周；土地招拍挂为滚动近 1 个月；政策长期保留并随周报追加。
37. 项目范围同时包含审批类、备案类和核准类，不限制最新项目阶段，项目总投资必须严格大于 5000 万元。
38. 项目统一通过财汇 MCP 的投资建设项目检索获取，并在接口返回后复核日期、地区、立项类型和金额边界。
39. 项目表格仅展示备案日期、地区、项目名称、总投资（万元）、项目主体、国标行业一级和最新项目阶段，并采用横向滚动宽表；筛选项包括省份、立项类型、三个固定投资金额区间、国标行业一级和最新项目阶段。项目和土地每页 30 条，政策每页 6 条。
